# Waple 업무일지 MCP

Claude / Claude Code에서 오늘 한 작업을 수집해 Waple 업무일지 초안을 만들고,
승인하면 Waple에 실제로 등록까지 해주는 MCP 서버입니다.

---

## 1. 프로젝트 목적

미래내일 일경험 팀 프로젝트에서 진행하는 Waple HR SaaS 플랫폼 연동 기능 중,
**업무일지 MCP 개발**을 담당하는 저장소입니다.

> 직원이 Claude 또는 Claude Code를 사용해 하루 동안 수행한 작업을 수집·정리하여
> Waple 업무일지 초안을 만들고, 사용자가 내용을 확인하고 승인하면 Waple에
> 등록하는 기능

기존 AI HR Report(EXAONE 기반 리포트 생성) 과업과는 별개이며, 현재 이 저장소의
중심은 **Claude 작업 기록과 Waple REST API를 연결하는 업무일지 MCP**입니다.

### 현재 범위가 아닌 기능

아래는 별도 요구사항이 확정되기 전까지 이 프로젝트의 구현 범위에 포함하지 않습니다.

- DB 직접 조회, HR DB 연결
- EXAONE 기반 HR 리포트 생성
- 직원 성과 평가, 직무 적합도, 이직 위험도, 조직 기여도 산출
- 사용자 승인 없는 완전 자동 등록

## 3. 전체 시스템 구조

```
사용자
  ├─ Claude Code (로컬, stdio)          ─┐
  ├─ Claude Code (원격, --header)        │
  ├─ Claude 데스크톱 앱 (로컬, stdio)    │  자연어 요청
  └─ Claude 데스크톱 앱 (원격)           │  ("업무일지 만들어줘" / "등록해")
       └ mcp-remote 브리지 경유          │
                                         ▼
                      MCP 서버 (server.py, 이 저장소)
                      ├─ stdio            ← 로컬 실행, .env의 키 사용
                      └─ streamable-http  ← 원격 배포, x-api-key 헤더 사용
                                    │
        ├─ waple_login     → GET  /api/api-key/validate
        ├─ tasklog         → 로컬 Git(commit/status/diff) + 세션 로그 수집
        ├─ chat_tasklog    → 대화 기반 근거를 인자로 받아 규격화 (외부 호출 없음)
        └─ submit_worklog  → GET/POST /api/mcp/diary
                                    │
                                    ▼
                        Waple 서버 ([WAPLE_BASE_URL])
                                    │
                                    ▼
                    업무일지 DB (Lexical JSON으로 저장)
```

- 하나의 `server.py`가 **stdio와 Streamable HTTP 두 가지 transport**를 모두 지원합니다.
- `tasklog`는 로컬 Git 저장소와 Claude Code 세션 로그를 읽으므로 **로컬(stdio) 전용**이며,
  HTTP(원격) 모드에서는 호출이 차단됩니다. 원격 환경에서는 `chat_tasklog`를 사용합니다.
  (7/29 정정: 종전 기록은 "원격에서 호출하면 초안은 생성되나 수집 항목이 모두
  비어 있다"였으나, 재실측 결과 **배포 서버 자신의 Git 저장소가 그대로 수집**되어
  사용자가 하지 않은 커밋이 초안에 채워졌습니다. 원격 서버가 읽을 수 있는 것은
  사용자 PC가 아니라 서비스의 `WorkingDirectory`이기 때문입니다. 이중 transport
  구조를 유지하는 이유입니다.)
- claude.ai **웹**은 커스텀 헤더를 지원하지 않아 연결할 수 없습니다. 채팅 UI에서
  쓰려면 데스크톱 앱 + `mcp-remote` 브리지를 사용합니다(7-2절).
- Waple과의 통신은 `waple_login`, `submit_worklog` 두 도구에서만 발생합니다.
- 인증정보는 stdio 모드에서만 `llm팀/.env`에 저장되며 Git에 올라가지 않습니다.
  HTTP 모드에서는 저장하지 않고 요청 헤더의 키를 그대로 사용합니다.

## 4. 기능 동작 흐름

1. **로그인**: 사용자가 Waple API 키를 입력하면 `waple_login` 도구가 키를 검증하고 로컬에 저장
2. **초안 생성**: 사용자가 "업무일지 초안 만들어줘" 요청 → `tasklog` 도구가 Git 커밋·status·diff 규모를 수집 → 3항목 형식 초안 생성
3. **확인/수정**: 사용자가 초안 확인 → 수정 필요하면 `tasklog`를 새 값으로 다시 호출
4. **등록**: 사용자가 "이 내용으로 등록해" 등 **명확한 승인 표현**으로 요청
5. `submit_worklog` 도구가 등록 직전 API 키를 한 번 더 검증
6. 같은 날짜 기존 일지가 있는지 먼저 조회 → 있으면 "덮어씁니다" 안내
7. `POST /api/mcp/diary`로 Waple에 실제 등록
8. 성공/실패 결과를 사용자에게 명확히 보고

> 승인 표현이 없으면(`정리해줘`, `검토해줘`, `초안 만들어줘`, `수정해줘`,
> `어떻게 보이는지 알려줘` 등) 절대 등록하지 않습니다.

## 6. 환경변수 설정

`llm팀/.env` 파일(직접 만들 필요 없음 — `waple_login` 실행 시 자동 생성)에
아래 값이 저장됩니다.

```env
WAPLE_API_KEY=발급받은_API_키
WAPLE_BASE_URL=[WAPLE_BASE_URL]
```

| 변수 | 필수 여부 | 설명 |
|---|---|---|
| `WAPLE_API_KEY` | 필수 | `waple_login` 실행 시 자동 저장. 직접 입력 비권장 |
| `WAPLE_BASE_URL` | 선택 | 미입력 시 `[WAPLE_BASE_URL]`가 기본값으로 사용됨 |

`.env`는 Git에 절대 올리지 않으며, `.gitignore`에 `.env`, `.env.bak`, `*.bak`이
포함되어 있는지 항상 확인합니다. 화면 공유·캡처 시에도 API Key가 보이는 줄은
반드시 가립니다.

**Waple API 키는 "재발급 = 기존 키 즉시 만료" 구조가 아닙니다.** 여러 개의
키를 동시에 발급받아 개별적으로 관리·삭제하는 **다중 키 구조**입니다
(6/27 실측 확인). 기존 키를 직접 삭제하지 않는 한 계속 유효하므로, 새 키를
발급받아도 이전 키로 로그인된 세션은 그대로 동작할 수 있습니다. 키를
정리하려면 Waple → 환경설정 → API 설정에서 개별 삭제해야 합니다.

> **주의**: 위 구조 때문에 키가 노출되었을 때 새 키를 발급하는 것만으로는
> 부족합니다. **노출된 기존 키를 반드시 삭제**해야 무효화됩니다.

> **HTTP(원격) 모드에서는 `.env`를 사용하지 않습니다.** 요청 헤더의
> `x-api-key`만 사용하며, 서버에 키를 저장하거나 `.env` 값으로 폴백하지
> 않습니다(사용자 간 키 공유 방지, 7/17).

## 7. MCP 서버 연동 방법

MCP 서버는 사내 서버에 배포되어 있어, **레포를 클론하지 않아도 Waple API 키만
있으면 연동할 수 있습니다.** 아래 표에서 본인 환경에 맞는 절을 참고하세요.

| 사용 환경 | 연결 방식 | 절 | 사전 준비 |
|---|---|---|---|
| Claude Code | 원격 (권장) | 7-1 | Waple API 키 |
| Claude 데스크톱 앱 (일반 채팅) | 원격 (권장) | 7-2 | Waple API 키, Node.js 18+ |
| claude.ai 웹 | ❌ 불가 | 7-3 | — (제품 제약, 사유 기재) |
| Claude Code | 로컬 설치 | 7-4 | 레포 클론, Python 가상환경 |
| Claude 데스크톱 앱 | 로컬 설치 | 7-5 | 레포 클론, Python 가상환경 |

**API Key 발급 방법**: `[WAPLE_BASE_URL]` 로그인 → 환경설정 → API 설정 →
`업무일지 등록/수정`, `업무일지 조회` 체크박스 둘 다 체크 → 발급하기

> **원격과 로컬의 기능 차이**
> 원격 서버는 사용자 PC의 파일에 접근할 수 없으므로, Git 커밋·변경 파일·토큰
> 사용량을 자동 수집하는 `tasklog`는 HTTP 모드에서 **차단**됩니다. 차단하지
> 않으면 배포 서버 자신의 저장소가 수집되어, 사용자가 하지 않은 작업이
> 업무일지에 사실처럼 실립니다(7/29 실측). 원격 환경에서는 대화 내용을
> 근거로 삼는 `chat_tasklog`를 사용하고, Git 기반 자동 수집이 필요하면
> 로컬 설치(7-4)를 사용하세요.

### 7-1. 원격 연동 — Claude Code (7/21 검증 완료)

```bash
claude mcp add --transport http waple-remote https://[SERVER_URL]/llm/mcp --header "x-api-key: 발급받은키"
claude mcp list   # waple-remote ... Connected 확인
```

| 옵션 | 의미 |
|---|---|
| `--transport http` | stdio가 아닌 Streamable HTTP로 연결 |
| `--header` | 요청마다 전달할 헤더. `x-api-key`를 이 방식으로 전달 |

원격 모드에서는 키가 서버에 저장되지 않으므로 `waple_login`을 별도로 실행할
필요가 없습니다(헤더의 키를 요청마다 사용).

> **로컬과 원격을 동시에 등록하면 도구 이름이 같아 어느 쪽이 호출됐는지
> 구분되지 않습니다.** 원격 경로를 검증할 때는 `claude mcp remove waple-tasklog`로
> 로컬을 잠시 제거하고, 끝나면 `git checkout .mcp.json`으로 원복하세요.

### 7-2. 원격 연동 — Claude 데스크톱 앱 (7/21 신규 검증)

데스크톱 앱의 일반 채팅에서 원격 서버를 사용하는 방법입니다. **비개발자가
레포·Python 없이 사용할 수 있는 경로**입니다.

**중요**: `claude_desktop_config.json`은 **stdio 서버만 인식**합니다.
Claude Code의 `.mcp.json`처럼 `"type": "http"` + `"url"` + `"headers"`를
적으면 항목이 조용히 무시되거나 설정 전체가 로드되지 않습니다.
따라서 `mcp-remote`(공개 npm 패키지)를 **stdio ↔ HTTP 브리지**로 끼웁니다.

```
사용자 ─ Claude 데스크톱 앱 ─(stdio)─ mcp-remote ─(HTTPS)─ 원격 MCP 서버
```

**사전 준비**: Node.js 18+ (`node -v`로 확인)

**설정 절차**

1. 데스크톱 앱 → 설정 → 개발자 → 구성 편집 → `claude_desktop_config.json`
   (위치: `%APPDATA%\Claude\`)
2. `mcpServers` 안에 아래 항목을 추가합니다(기존 항목은 지우지 않습니다).

```json
{
  "mcpServers": {
    "waple-remote": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://[SERVER_URL]/llm/mcp",
        "--transport", "http-only",
        "--header", "x-api-key:${WAPLE_API_KEY}"
      ],
      "env": {
        "WAPLE_API_KEY": "발급받은키"
      }
    }
  }
}
```

| 항목 | 이유 |
|---|---|
| `-y` | npx 설치 확인 프롬프트를 자동 승인. 없으면 첫 실행이 멈춤 |
| `--transport http-only` | SSE 협상을 건너뜀. 없으면 실행마다 약 5초 지연 |
| `x-api-key:${...}` | **콜론 뒤에 공백을 넣지 않습니다.** 공백이 있으면 인자 파싱이 깨져 헤더가 전달되지 않습니다 |
| `env` 참조 | 키를 `args`에 직접 쓰면 프로세스 목록(작업관리자·`tasklist`)에 명령줄 전체가 노출됩니다 |

3. 저장 후 앱을 **완전 종료**합니다 — 창 X가 아니라 트레이 아이콘 우클릭 →
   종료 후 재실행해야 설정을 다시 읽습니다.
4. 설정 → 개발자 → 로컬 MCP 서버에서 `waple-remote`가 `running`인지 확인합니다.

> **`running` 표시만으로는 인증 성공을 확인할 수 없습니다.** 브리지 프로세스는
> 키가 잘못돼도 기동됩니다. 채팅에서 `와플 로그인해줘`를 실행해 로그인 성공
> 응답이 오는지까지 확인하세요. 이때 **키를 입력하지 않아도 성공**하면 헤더가
> 정상 전달된 것입니다(7/21 실측).

### 7-3. claude.ai 웹 — 연동 불가 (제품 제약)

웹의 커스텀 커넥터 추가 UI는 인증 방식으로 **OAuth만 지원**하며, 임의 헤더를
입력하는 항목이 없습니다(원격 HTTPS URL 유무의 문제가 아닙니다). URL만
등록하면 목록에는 나타나지만 인증이 통과되지 않습니다. 임의 헤더 지정
기능(`static_headers`)은 조직 관리자 전용 베타입니다.

**우회 방법**: 채팅 UI에서 사용하려면 **데스크톱 앱 + `mcp-remote` 브리지**(7-2)를
사용합니다. 데스크톱 앱은 웹 UI가 아닌 설정 파일 기반이라 커스텀 헤더 전달이
가능합니다.

### 7-4. 로컬 설치 — Claude Code

Git 커밋·변경 파일·토큰 사용량 자동 수집(`tasklog`)이 필요한 경우 사용합니다.
5절(설치)을 먼저 완료한 뒤, `llm팀` 폴더에서 Claude Code를 열고:

```
와플 로그인해줘
```

Claude가 API 키를 요청하면 발급받은 키를 입력합니다. 로그인에 성공하면
`llm팀/.env`에 API 키가 자동 저장되며, 다음부터는 저장된 키를 자동으로
불러오므로 매번 로그인할 필요가 없습니다. 키를 Waple에서 삭제하면 다시
`waple_login`으로 등록해야 합니다.

> `.env` 저장은 **stdio(로컬) 모드에서만** 동작합니다. HTTP 모드에서는 사용자
> 간 키 공유를 막기 위해 저장·폴백을 모두 차단합니다(7/17).

### 7-5. 로컬 설치 — Claude 데스크톱 앱

로컬 서버를 데스크톱 앱의 일반 채팅에서 사용하는 방법입니다. 7-4로 한 번
로그인해 `.env`에 키를 저장해 둔 상태여야 합니다.

1. 데스크톱 앱 → 설정 → 개발자 → 구성 편집 → `claude_desktop_config.json`
2. `mcpServers` 안에 아래 항목을 추가 (경로는 본인 환경에 맞게 수정):

```json
{
  "mcpServers": {
    "waple-tasklog": {
      "command": "C:\\study\\uxis\\2026-uxis-mirae\\.venv\\Scripts\\python.exe",
      "args": ["C:\\study\\uxis\\2026-uxis-mirae\\llm팀\\server.py"]
    }
  }
}
```

**주의사항 3가지**

- **기존 내용을 지우지 말 것.** 이 파일에는 앱의 다른 설정이 함께 들어
  있습니다. `mcpServers` 항목만 추가하고, 닫는 `}` 뒤 쉼표(`,`)를 빼먹지
  않아야 합니다 (JSON 오류 시 앱이 설정 전체를 무시).
- **UTF-8로 저장** (한글 경로 포함이므로), 역슬래시는 2개(`\\`)로 이스케이프.
- 저장 후 **앱 완전 재시작** — 창 X가 아니라 트레이 아이콘 우클릭 → 종료
  후 재실행해야 설정을 다시 읽습니다.

등록 확인: 새 채팅 → 입력창 도구 아이콘 → `waple-tasklog` 도구 4개 표시.

> `.env` 로딩은 실행 위치(cwd)가 아니라 `server.py`가 있는 폴더 기준으로
> 고정되어 있어(7/11 수정) 데스크톱처럼 cwd가 다른 환경에서도 저장된 키를
> 읽습니다.

## 8. 제공 도구 (MCP Tools)

| 도구 | 역할 | 입력 |
|---|---|---|
| `waple_login` | API 키를 입력받아 검증하고 로컬에 저장 | `api_key`(필수) |
| `tasklog` | 오늘 Git 커밋·status·diff 규모를 수집해 3항목(오늘 한 일/상세 진행 내용/내일 계획) 형식 업무일지 초안 생성. **로컬(stdio) 전용 — HTTP 모드에서는 차단** | `memo`(선택), `tomorrow_plan`(선택) |
| `chat_tasklog` | 일반 채팅(Git 접근 불가 환경)용 초안 생성 — Claude가 정리한 근거를 인자로 받아 3항목 형식으로 규격화 | `activities`(선택), `created_files`(선택), `memo`(선택), `tomorrow_plan`(선택), `needs_confirmation`(선택) |
| `submit_worklog` | 승인된 내용을 Waple에 실제 등록 | `memo`(필수), `target_date`(선택), `title`(선택) |

### waple_login 상세

- API 키를 입력받으면 `GET /api/api-key/validate`로 유효성을 검증합니다.
- 유효한 키는 `llm팀/.env`에 저장하고, 전역변수와 `os.environ`을 즉시 갱신합니다.
- `diary:write` scope가 없는 키는 저장은 하되 경고 메시지를 반환합니다.
- 잘못된 키(401)는 저장하지 않습니다.
- **HTTP 모드에서는 `.env` 저장을 차단**합니다(7/17). 원격 환경에서는 요청
  헤더의 키가 그대로 사용되므로 서버에 키를 남길 이유가 없고, 남기면 다른
  사용자에게 공유될 위험이 있습니다.

### tasklog 상세

- **HTTP(원격) 모드에서는 호출이 차단됩니다.** 이 도구가 읽는 대상은 서버
  프로세스가 실행 중인 컴퓨터의 저장소이지 사용자의 컴퓨터가 아니므로,
  원격에서 그대로 실행하면 배포 서버의 커밋이 사용자 업무일지에 실립니다.
  `_REQUEST_IS_HTTP`로 판별해 수집 이전에 조기 반환하며, 이때 초안 캐시도
  건드리지 않아 `submit_worklog`가 잘못된 초안을 집어갈 경로가 없습니다.
  원격에서는 `chat_tasklog`를 사용하세요 (7/29).
- `memo`: Git 기록에 안 남는 활동(회의, 자료 조사 등)을 사용자가 직접
  입력하면 "오늘 한 일" 항목에 반영됩니다.
- `tomorrow_plan`: "내일(향후) 계획" 항목에 들어갈 내용입니다. 비어 있으면
  "(미기재)"로 표시됩니다.
- 초안은 화면 표시용(안내문 포함)과 실제 Waple 전송용(3항목+구분선만) 두
  가지로 나뉘며, 전송용 원본은 서버 메모리(`_LAST_DRAFT`)에 저장해
  `submit_worklog`가 그대로 사용합니다. Claude가 등록 시점에 내용을
  재구성하면서 구분선이나 `tomorrow_plan`이 유실되는 걸 막기 위한 장치입니다.
- 초안을 수정하고 싶으면 화면 텍스트만 고치지 말고 `tasklog`를 새 값으로
  다시 호출해야 합니다. 그렇지 않으면 화면에 보이는 내용과 실제 등록되는
  내용이 달라질 수 있습니다.
- **`_LAST_DRAFT` 캐시 동작 (1회용, PR#6 리뷰 반영)**: 같은 날짜에 저장된
  초안이 있으면 `submit_worklog`는 호출자가 전달한 memo 대신 저장된 원본을
  사용합니다. 이 캐시는 1회용입니다.
    - **등록 성공 시**: 캐시를 즉시 비웁니다. → 같은 날짜에 tasklog 재호출
      없이 예전 초안이 재사용되는 stale 위험을 방지합니다.
    - **등록 실패 시**: 캐시를 유지합니다. → 재시도 시 원본이 그대로 다시
      전송되어, Claude 재구성으로 인한 형식 손실(버그 #1)이 재시도 경로에서
      재발하지 않습니다.
    - 세션 메모리라 서버 재시작 시 초기화됩니다.
- **사용자별 캐시 스코핑 (7/17)**: 원격 서버는 여러 사용자가 동시에 쓰므로
  캐시를 `_LAST_DRAFTS` 딕셔너리로 분리했습니다. 스코프 이름은 API 키의
  sha256 앞 16자리라 **키 원문이 딕셔너리 키로 노출되지 않습니다.**
  stdio(로컬)는 `_local` 스코프를 쓰며 기존 `_LAST_DRAFT`와 같은 객체를
  공유하므로 동작이 바뀌지 않습니다.

  tasklog/chat_tasklog 재호출 없이 바로 `submit_worklog`가 불리는 경로에서는
  저장된 초안이 없으므로 전달받은 memo를 그대로 쓰되 형식 경고를 표시합니다.

### chat_tasklog 상세 (보완③ 채팅 커넥터, 7/11 추가)

Git에 접근할 수 없는 일반 채팅 환경 전용 초안 생성 도구입니다. Claude Code
에서는 Git 기반의 `tasklog`를 사용하세요.

- **근거 전달 구조** (`docs/connector-design.md` v1): 원격/채팅 환경의 MCP는
  대화 내용과 생성 파일에 직접 접근할 수 없으므로, **Claude가 근거를 정리해
  도구 인자로 전달**하고 서버는 규격화만 담당합니다.
    - `activities`: 이 대화에서 실제 수행이 확인된 작업 → "오늘 한 일"에
      `[대화 기반]` 라벨로 반영
    - `created_files`: 대화 중 생성/수정한 파일명 → "상세 진행 내용"에
      `[생성 파일]` 라벨로 반영
    - `memo`: 대화에 없는 활동을 사용자가 직접 불러준 내용 → `[사용자 메모]`
- **사실성 장치**: 수행 여부가 불분명한 항목은 `needs_confirmation`으로
  분리하면 **Waple 전송 본문에서 제외**되고 화면의 "사용자 확인 필요"에만
  표시됩니다 (지침 6번: 추정은 사실처럼 작성하지 않고 분리).
- 생성된 초안은 초안 캐시에 저장되어 기존 `submit_worklog` 승인
  흐름을 그대로 재사용합니다 (같은 날 `tasklog`와 번갈아 호출하면 마지막
  호출이 캐시를 덮어씀 = 마지막으로 화면에 보여준 초안이 등록됨).
- 초안의 `[대화 기반]` 항목은 Git 기록이 아닌 **자기 보고**이므로, 화면에
  경고와 함께 등록 전 직접 확인을 요구합니다.
- 토큰 사용량은 Claude Code 세션 로그가 없는 환경이라 "집계 대상 아님"으로
  표기합니다(추정값을 넣지 않습니다).

⚠️ 알려진 한계 (7/12 기준)

  요약 표시가 재발할 수 있습니다.

### submit_worklog 상세

- API 키가 없으면 "먼저 `waple_login`으로 등록하세요" 안내
- 등록 직전에 `GET /api/api-key/validate`로 키를 한 번 더 검증
- 재검증 요청이 네트워크 오류로 실패하면 **등록을 중단**하고 사용자에게
  알림 (7/3 수정 — 아래 11번 버그 수정 내역 참고)
- 키가 만료/무효화된 경우 등록을 차단하고 재로그인 안내

> `submit_worklog`는 사용자의 명확한 승인 표현(`등록해`, `이 내용으로 올려`,
> `승인`, `Waple에 저장해` 등)이 없으면 호출하지 않도록 도구 설명에
> 명시되어 있습니다. `정리해줘`, `초안 만들어줘`, `검토해줘`,
> `어떻게 보이는지 알려줘`, `수정해줘`는 승인으로 간주하지 않습니다.
> **이 통제는 코드가 아니라 프롬프트 지시에 의존합니다**(11-2절 6·7 참고).

## 9. Waple API 연동 방식

| API | 메서드 | 용도 |
|---|---|---|
| `/api/api-key/validate` | GET | API Key 유효성 및 scope 확인 |
| `/api/mcp/diary` | GET | 날짜 범위로 기존 업무일지 조회 |
| `/api/mcp/diary` | POST | 업무일지 등록/수정 (Upsert) |

- 인증: 모든 요청에 `X-Api-Key` 헤더 필요
- **주의**: API 명세서는 응답 필드를 `"success"`로 적고 있지만, 실제 응답은
  `"status"`입니다. 코드에서는 `status` 기준으로 처리합니다.
- **scope 필드명**: `/api/api-key/validate` 응답의 scope 필드는 실측 결과
  `"scope"`(단수, 콤마 구분 문자열)로 확인됐습니다(7/3). 코드는 `scopes`(복수)
  케이스도 함께 처리하도록 방어적으로 작성되어 있습니다.
- 같은 날짜에 이미 등록된 일지가 있으면 새로 만들지 않고 자동으로 덮어씁니다.
- `memo`는 plain text로 보내면 서버가 내부적으로 Lexical JSON으로 변환해
  저장합니다. 구분선(가로줄)은 plain text로도 정상 렌더링되는 것을 확인했으나,
  체크박스 렌더링 여부는 미확인 상태입니다.

### ⚠️ AI 에이전트에게 키 조회를 맡길 때의 위험 (7/21 실제 사례)

"`.env`에서 키를 찾아 로그인해줘"처럼 요청하면, Claude가 `grep`·`cat` 등으로
**키 값을 터미널에 그대로 출력한 뒤** 도구에 전달하는 경우가 있습니다.
이때 키는 터미널 스크롤백과 세션 로그(`~/.claude/projects/*.jsonl`)에
평문으로 남습니다.

- 요청 시 **"키 값은 화면에 출력하지 마"** 를 함께 지시합니다.
- 노출된 경우 새 키 발급만으로는 부족하며, **Waple에서 기존 키를 삭제**해야
  무효화됩니다(6절 다중 키 구조 참고).
- 애초에 키가 필요한 작업은 Claude에게 파일을 뒤지게 하지 말고 사용자가
  직접 값을 지정하는 편이 안전합니다.

### ⚠️ `mcp-remote` 브리지 사용 시 키 노출 (7/21 확인)

데스크톱 원격 연동(7-2절)에 사용하는 `mcp-remote`는 **전달받은 헤더를 그대로
표준 출력에 기록**합니다.

```
[10864] Using custom headers: {"x-api-key":"waple-..."}
```

우리 코드가 아닌 외부 패키지의 동작이므로 수정할 수 없습니다. 다음을 지킵니다.

- 키는 반드시 `env`에 두고 `args`에서는 `${WAPLE_API_KEY}`로 참조합니다
  (프로세스 목록 노출 방지).
- 데스크톱 앱의 **로그 보기** 화면과 MCP 로그 파일에 키가 남습니다.
  화면 공유·시연·이슈 첨부 시 이 로그를 그대로 캡처하지 않습니다.
- 브리지를 터미널에서 직접 실행해 본 경우, 실행 후 스크롤백을 지웁니다.

### 기록 무결성 — 근거 파일 생성 시 셸 혼용 사고 (7/30)

`docs/evidence/multiline_input_evidence.txt`를 처음 만들 때 Git Bash 전용
구문 `{ ... } > 파일`을 PowerShell에서 실행하였습니다. PowerShell에서
`{ }`는 스크립트 블록 객체라 실행되지 않고 블록 내용이 글자 그대로
저장되었고, PowerShell의 `>`는 기본 인코딩이 UTF-16LE라 인코딩까지
섞였습니다. 파일은 정상 생성되고 이름·크기도 있어 눈으로는 문제가 없어
보였습니다 — 7/29 원격 tasklog 건(서버 자신의 커밋이 초안에 채워지던
문제)과 같은 유형입니다. 비어 있으면 알아채지만, 그럴듯하게 채워져 있으면
넘어갑니다. 재발 방지: 셸을 혼용하지 않고, 근거 파일은 생성 직후 반드시
내용을 열어서 확인합니다.

      도움말이 "외부 공개 배포 시 0.0.0.0"을 안내하고 있어 방어가 경고 없이
      꺼질 수 있는 구조였다. 허용 Host·Origin을 코드에 직접 명시하고, SDK 자동
      기본값의 상위집합으로 구성해 기존 경로 회귀 없음. nginx의 Host 재작성은

      배포 서버 실측으로 차단 응답·서버 로그 확인, `test_connector.py` 3케이스 추가.
      기존 "Git·토큰이 비어 있음" 서술 정정 (7/29, 11-4절)
- [x] 원격 커넥터 인증 실패 안내 문구 정정 — HTTP 모드에서 `x-api-key` 헤더가
