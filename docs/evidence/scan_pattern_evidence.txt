## 개요
build_pdf.py 의 verify() 는 공개 레포용 PDF에 배포 서버 정보가 섞이면
중단하도록 되어 있었다. 그러나 검사 패턴은 IPv4 / user@host / :포트 /
ssh -p 네 가지뿐이었고, 도메인을 판정하는 패턴이 존재하지 않았다.

인계 메모에는 이 문제가 "와일드카드 표기가 패턴을 통과한다"로 기록되어
있었으나, 실측 결과 원인은 그보다 넓었다. 와일드카드 여부와 무관하게
도메인 자체가 검사 대상이 아니었다.

또한 :포트 패턴이 시각 표기(17:02:12)를 포트로 오탐하고 있었다. 문서에
검증 시각을 적는 순간 검사가 중단되는 구조였다.

[6] 남은 한계
------------------------------------------------------------------------------
- 도메인 검사는 TLD 목록 기반이므로 목록에 없는 TLD 는 통과한다.
  값이 아니라 형태로 검사하더라도, 형태를 좁게 잡으면 뚫린다는 점은
  이번 건에서 그대로 확인되었다. 목록은 필요할 때 넓힌다.
- .dev / .app 은 파일명·식별자와 형태가 겹쳐 오탐 가능성이 있다.
  현재까지 실제 문서에서는 발생하지 않았다.
- 허용 목록(ALLOWED_*)에 항목을 추가할 때는 "이 값은 공개해도 되는가"를
  매번 확인해야 한다. 오탐이 번거롭다고 넓히면 검사기가 다시 눈이 먼다.
