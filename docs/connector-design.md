## 1. 배경

5주차 회의(2026-07-01, 멘토 박지웅 참석)에서 LLM팀 보완 과업이 확정되었으며, 그중 두 가지가 커넥터 확장에 해당합니다.

| 과업 | 내용 |
| --- | --- |
| 보완② 근거 수집 확장 | 근거를 로컬 Git 커밋만이 아니라 **Claude 대화/명령까지 합쳐서** 업무일지를 생성 |
| 보완③ 일반 채팅 지원 | Claude **일반 채팅(커넥터=원격 MCP)** 환경에서도 업무일지 등록이 가능하도록 확장 (대상: 기획자 등 비개발자) |

**6주차 회의(2026-07-10) 추가 확정**: 보완③의 근거 소스 = **대화 내용 + 생성한 파일** (멘토 지시, 아래 4절).

## 2. 현재 확정된 아키텍처 (v0 기준)

현재 구현된 업무일지 MCP는 **Claude Code(개발자) 환경**을 전제로 합니다.

- 도구 3종: `waple_login`, `tasklog`, `submit_worklog`
- 근거 소스: **로컬 Git 커밋 로그** + Claude Code 세션 로그(토큰 사용량, 7/10 추가)
- 등록 흐름: 초안 미리보기 → 사용자 승인 → `POST /api/mcp/diary`(upsert) → 결과 확인

즉, 현재 구조는 **"로컬 파일·git에 접근할 수 있다"**는 전제 위에 서 있습니다.

## 3. 보완② — 근거 수집 확장 (Claude Code 환경)

### 방향
현재 근거인 Git 커밋에 **Claude Code 세션 내 대화/명령 기록**을 추가합니다. 커밋에는 남지 않는 작업(자료 조사, 설계 논의, 오류 진단 과정 등)을 근거로 반영하기 위함입니다.

### 확정된 부분
- 입구는 그대로 **Claude Code**이므로 로컬 git 접근 전제는 유지됩니다.
- 기존 `tasklog`의 커밋 수집 로직은 재사용 가능합니다.
- **세션 로그 파싱 기반 확보(7/10)**: 토큰 사용량 기능(`_collect_today_token_usage`)으로
  `~/.claude/projects/<프로젝트>/*.jsonl`을 읽는 공통 로직이 이미 구현·검증되었습니다.
  대화 기록도 같은 파일에 있으므로 이 파서를 확장하는 방식으로 접근합니다.

### 🟡 미확정 (확인 필요)
- 대화/명령 기록을 **어떤 형태로 근거화**할지 (원문 저장 vs 요약 vs 작업 단위 매핑).
- 커밋 근거와 대화 근거를 **하나의 업무 항목으로 병합하는 기준** — 지침 7의 "목적 기준 분류"를 대화 기록에도 동일 적용할지.
- 대화 기록이 길 때의 **개인정보·민감정보 필터링** 위치(지침 13 준수).

## 4. 보완③ — 일반 채팅(커넥터) 지원

### 목적
Claude Code를 쓰지 않는 **비개발자(기획자 등)**도 업무일지를 등록할 수 있게 합니다. 같은 계정이므로 데이터는 묶되, **입구(코드 / 채팅)를 둘 다** 지원하는 것이 목표입니다.

### ✅ 근거 소스 확정 (2026-07-10, 6주차 회의 멘토 지시)
채팅 환경의 업무일지 근거 = **① 대화 내용 + ② 생성한 파일**.
(기존 v0의 🔴 "채팅 환경 근거 수집 아키텍처 미확정"은 이 지시로 해소됨.)

### 핵심 제약 (여전히 유효)
Claude **일반 채팅(웹) 환경은 사용자 로컬의 git 로그·파일에 접근하지 못합니다.**
따라서 현재 `tasklog`의 로컬 수집 방식은 채팅 환경에서 사용할 수 없습니다.

### 🟡 기술 검증 필요 — 근거 전달 구조
확정된 근거(대화 + 생성 파일)를 **원격 MCP 서버가 어떻게 받는가**가 남은 설계 포인트입니다.

- 원격 MCP 서버는 웹 채팅의 대화 이력·생성 파일(아티팩트)에 **직접 접근하는 표준 경로가 없음**.
- 따라서 현실적인 구조는 다음과 같이 역할을 나누는 방식입니다:

| 역할 | 담당 | 내용 |
| --- | --- | --- |
| 근거 수집·요약 | **Claude(채팅)** | 현재 대화에서 수행한 작업과 생성한 파일 목록을 스스로 정리 |
| 초안 규격화 | **원격 MCP 도구** | Claude가 정리한 근거를 도구 인자(예: `activities`, `created_files`)로 받아 3항목 양식으로 조립, `_LAST_DRAFT` 저장 |
| 승인·등록 | **원격 MCP 도구** | 기존 `submit_worklog` 흐름과 동일 (키 재검증, 중복 안내, 1회용 캐시) |

- 이 구조에서는 근거의 사실성이 Claude의 자기 보고에 의존하므로,
  지침 6("확인할 수 없는 작업은 사실처럼 작성하지 않는다") 준수를 위해
  초안의 근거 표시를 `[대화 기반]` / `[생성 파일: 파일명]`으로 구분하고
  "사용자 확인 필요" 섹션의 비중을 Claude Code 버전보다 키웁니다.

### 두 입구 비교 (갱신)

| 구분 | Claude Code (개발자) | 일반 채팅 / 커넥터 (비개발자) |
| --- | --- | --- |
| 로컬 git 접근 | 가능 | 불가 |
| 파일 변경 확인 | 가능 (git status/diff) | 불가 (Claude가 생성 파일을 자기 보고) |
| 주 근거 소스 | Git 커밋 + 세션 로그 | **대화 내용 + 생성한 파일 (확정)** |
| 근거 신뢰 수준 | 기록 기반 (검증 가능) | 자기 보고 기반 (사용자 확인 필수) |

### 🟡 미확정 (확인 필요)
- 사용자가 직접 입력하는 작업 메모의 포함 방식 (Claude Code 버전의 `memo`와 동일 규칙 적용 예상).
- 동일 계정의 **코드/채팅 데이터 통합 및 중복 등록 방지** 방식(지침 12) — Waple upsert가 같은 날짜를 덮어쓰므로, 두 입구를 같은 날 쓰면 나중 등록이 앞선 등록을 덮어쓰는 문제 → 등록 전 기존 일지 조회 안내(기존 구현)로 1차 방어, 병합 정책은 추가 논의.
- 원격 MCP 배포 위치(사내 미니PC 서버 예상)와 인증 흐름(채팅 커넥터에서 `waple_login` 동작 방식).
